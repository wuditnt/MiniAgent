# 演示大纲

目标：给出逐页可执行的大纲 —— 每页说什么、放什么图、口头讲什么。

## 适用与不适用

- 适用：汇报、方案评审、产品介绍、培训分享的分页大纲与讲稿。
- 不适用：直接生成 .pptx 成品（可另用文档技能落 Markdown）；需要设计稿。

## 第 0 步：确认要素

用 `ask_user` 一次问清（已说明的跳过）：

1. 受众：领导 / 客户 / 同事；
2. 时长（分钟）；
3. 场景：汇报进度 / 争取资源 / 方案评审。

页数默认按「时长 ÷ 1.5」估算，例如 15 分钟约 10 页。

## 步骤

1. **取素材**：`read_file` / `read_docx` / `read_xlsx` 读现有材料；缺数据时问用户要，不要编。
2. **定主线**：一句话结论 → 3–5 个支撑论点 → 行动建议。先给用户看主线，确认后再拆页。
3. **逐页展开**（见下方模板）。
4. **落盘**：`docs/<主题>-大纲.md`。

## 分页模板

```markdown
### P3 ｜ 三个渠道贡献了 82% 的营收
- 要点：直营 46% ／ 分销 24% ／ 线上 12%
- 图表：横向条形图，按占比排序
- 口播：营收高度集中，先守住直营，再补线上。
```

## 页面顺序

1. 封面（主题 + 一句话副标题 + 汇报人 / 日期）
2. 结论页（先给答案）
3. 目录（≤ 5 项）
4. 主体（每页一个论点，3–5 页一组）
5. 总结与下一步
6. Q&A / 附录（放细节数据）

## 输出规范

- 每页标题写成结论句，不写「现状分析」这类栏目名。
- 每页要点 ≤ 3 条，每条 ≤ 20 字。
- 图表只写「用什么图、表达什么」；数据页标注来源与时间。
- 口播每页 1–2 句，口语化，不重复页面文字。

## 约束

- 不写满屏文字，不把文档段落直接搬上页面。
- 不编造数字、案例、客户名。
- 用户没给数据时，在对应页写「待补数据」，不要填空值。
