# 会议纪要

目标：让没参会的人读完就知道「定了什么、谁在什么时候做什么」。

## 适用与不适用

- 适用：会议记录、录音转写稿、聊天记录整理成纪要。
- 不适用：凭空生成会议内容；替用户做决策。

## 第 0 步：确认信息

材料里缺会议主题 / 时间 / 参会人时，用 `ask_user` 一次问清（可多选跳过）。
用户说「不重要」就直接留空写「未记录」，不要追着问。

## 步骤

1. **通读材料**：粘贴文本直接读；文件用 `read_file` / `read_docx`；转写稿乱就先按时间切段。
2. **抽四类要素**：
   - 结论：已经拍板的事（不是讨论过程）；
   - 待办：谁、做什么、什么时候前完成；
   - 分歧：没定下来、需要再议的点；
   - 风险：被提到但没人认领的问题。
3. **结构化输出**：按下面的模板写，用 GFM 表格。
4. **落盘**：默认 `docs/<主题>-会议纪要.md`；用户说「发我」就直接在对话里给全文。

## 纪要模板

```markdown
# <会议主题> 会议纪要

| 项目 | 内容 |
| --- | --- |
| 时间 | 2026-01-01 14:00–15:00 |
| 参会 | 张三、李四 |
| 主持 | 张三 |

## 一、结论
1. ……

## 二、待办
| 事项 | 责任人 | 截止 | 状态 |
| --- | --- | --- | --- |
| …… | 李四 | 1月5日 | 待开始 |

## 三、待议
- ……

## 四、风险
- ……
```

## 自检清单

- [ ] 结论只写「已定」的，讨论过程没混进去
- [ ] 每条待办都有责任人和截止时间（确实没有就写「待定」）
- [ ] 没有虚构参会人、时间、承诺

## 约束

- 只写会上出现过的信息，不补充外部知识。
- 责任人没明确指定时写「待定」，不要按发言顺序猜。
- 口语转书面可以精简，但不能改变原意、不能加重承诺语气。
