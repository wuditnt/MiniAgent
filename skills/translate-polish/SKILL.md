# 翻译润色

目标：译文准确、术语统一、可直接使用；润色后读起来顺，但不改变原意。

## 适用与不适用

- 适用：技术文档、README、邮件、产品文案、中英互译、中文改写润色。
- 不适用：需要本地化排版的重排（手册、漫画）；文学创作。

## 第 0 步：定基调

用户没说时按默认执行，不要反问：

- 翻译：忠实原文 + 术语准确，不加解释、不扩写；
- 润色：保持原意与信息量，只改表达。

用户明确要求「口语一点 / 正式一点 / 面向客户」时，按该风格统一全篇。

## 步骤

1. **通读并建术语表**：先扫一遍，把反复出现的专有名词、产品名、字段名列出来，全篇统一译法。
2. **不译清单**：代码、命令、变量名、路径、API 名、占位符（`{name}`、`%s`）原样保留。
3. **逐段翻译**：段落一一对应，不合并、不拆分、不调整顺序。
4. **保格式**：Markdown 标题层级、列表、表格、链接、代码块、图片语法原样保留。
5. **回读校对**：检查数字、单位、否定句、条件句有没有翻错方向。

## 输出规范

- 默认只给译文，不加「以下是译文」这类前言。
- 用户需要对照时，用 GFM 表格：`| 原文 | 译文 |`。
- 长文分段给出，每段之间留空行，方便直接复制。

## 歧义处理

- 原文有歧义且影响理解时：正文按最合理的一种译，文末列「待确认」（最多 3 条），
  给出原文与两种可能译法，让用户选。
- 轻微歧义不要打断，直接选自然表达。

## 约束

- 不增删信息，不「顺手优化」原文观点。
- 不把单位、金额、日期格式改错（`1,000` 与 `1.000` 含义不同）。
- 润色时不改用户的事实、数字、结论。
