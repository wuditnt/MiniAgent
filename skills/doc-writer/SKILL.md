# 通用文档写作

目标：把零散需求与素材，写成读者能直接读懂、能直接存档的文档。

## 适用与不适用

- 适用：需求说明、操作手册、对外介绍、项目总结、通知与政策解读。
- 不适用：技术方案 / 架构设计（用「技术方案写作」）、数据分析（用「CSV 分析」）、
  会议记录整理（用「会议纪要」）、纯代码修改。

## 第 0 步：确认要素

只问真正影响结构的项，一次问完（`ask_user`，选项 ≤ 4 个）：

1. 读者：内部同事 / 客户 / 新人；
2. 篇幅：一页摘要 / 完整章节。

**不问交付格式**：默认出 HTML；用户明确说要 Markdown / Word / PDF 时才直接出对应格式。
用户已在需求里说明的不要再问。

## 步骤

1. **收集素材**：`list_dir` 看目录，`read_file` / `read_docx` / `read_pdf` 读已有材料；
   需要外部事实时用 `web_search`，读原文用 `fetch_url`，并记下来源与日期。
2. **先列大纲**：3–6 个一级标题，第一个是执行摘要（结论先行）。大纲先给用户看，一句话确认后再展开。
3. **写正文**：每节先给结论，再给依据；步骤写成有序列表；术语首次出现给一句定义。
4. **落盘**：默认用 `write_file` 写单文件 HTML 到 `docs/<主题>.html`：
   内联 CSS、系统中文栈、A4 阅读宽度（约 800px），不引用外链样式或图片；
   标题用 h1–h3，对比用 `<table>`，代码用 `<pre><code>`。
5. **自查**后给出可点击路径，并用一句话问：
   「需要我再出 Markdown / Word / PDF 版吗？」（不用 `ask_user`，不阻塞收尾）
6. **按需转换**（只在用户明确要时做，正文不重写）：
   - Markdown：`write_file` 写 `docs/<主题>.md`
   - Word：`write_docx` 写 `docs/<主题>.docx`（传 Markdown 正文）
   - PDF：`write_pdf` 写 `docs/<主题>.pdf`（传 Markdown 正文）

## 输出规范

- 标题层级最多三级，不用「以下是」「综上所述」这类空话开头。
- 对比信息用 HTML 表格；代码、命令、配置放 `<pre><code>`，保留缩进与换行。
- 数字与引用必须标来源；拿不到就写「未获取」，不要估。

## 自检清单

- [ ] 执行摘要里能读到最终结论
- [ ] 每个结论都有依据（数据 / 来源 / 代码位置）
- [ ] 术语前后一致，缩写首次出现有解释
- [ ] HTML 已落盘，页面无外链资源，表格与代码块显示正常

## 约束

- 不编造数据、链接、引用。
- 不覆盖用户已有文件：同名时加 `-v2` 后缀。
- 用户只要内容不要文件时，直接在对话里给全文，不落盘。
