# 调研简报

目标：用尽可能少的篇幅，回答一个具体问题，并让人能顺着来源自己复核。

## 适用与不适用

- 适用：选型对比、市场/竞品速览、技术方案调研、政策与数据查证。
- 不适用：需要访谈或内部数据的调研；纯写作任务。

## 第 0 步：把问题问清楚

用 `ask_user` 确认三件事（用户已说明的跳过）：

1. 要回答的具体问题（一句话）；
2. 时间范围（最近 3 个月 / 1 年 / 不限）；
3. 输出是「结论页」还是「对比 + 建议」。

## 步骤

1. **多角度检索**：用 `web_search` 至少 3 次，覆盖不同表述（中文 / 英文、产品名 / 品类名）。
2. **读原文**：对关键结论用 `fetch_url` 打开原始页面，取准确数字与发布日期。
3. **交叉验证**：每个关键数字至少 2 个独立来源；只有 1 个来源时明确标注「单一来源」。
4. **组织**：结论先行 → 证据表 → 风险与不确定 → 后续建议。
5. **落盘**：`reports/<主题>-调研简报.md`。

## 简报结构

```markdown
# <主题> 调研简报

> 结论：一句话回答第 0 步的问题。

## 关键结论
1. ……

## 证据
| 结论 | 来源 | 日期 |
| --- | --- | --- |
| …… | https://… | 2026-01 |

## 风险与不确定
- ……

## 建议
- ……
```

## 输出规范

- 一页读完：结论 ≤ 5 条，每条 ≤ 2 行。
- 趋势、占比适合图形时，附一个 ```echarts 代码块（合法 JSON，类别 ≤ 20）。
- 每个数字后面带来源与日期，链接必须是实际访问过的。

## 约束

- 严格区分「事实」与「推测」，推测前加「推测：」。
- 查不到就写「未找到可靠来源」，不编造数字、机构名、链接。
- 不把同一篇文章的转载当成多个来源。
