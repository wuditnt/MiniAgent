# 内联提问

## 用途

Agent 缺关键信息或需要用户抉择时，把问题**直接问在回复气泡里**，不必让用户自己去输入框回答。答案是同一轮继续执行的输入。

## 概念

- **`ask_user` 工具**：模型调用的核心工具，参数是问题 + 可选候选 + 是否允许自由输入。
- **询问通道**：后端把一个「提问请求」通过 UI 桥接推给前端；前端渲染卡片，用户点选或输入后回传答案。
- **不设超时**：离开多久都不会自动拒绝。
- **失效处理**：点停止 / 刷新 / 关闭页面（连接断开）按「未回答」处理，卡片转灰「已失效」，Agent 基于已有信息继续或说明所用假设。

## 使用方式

- 三档确认模式（ask / auto / full）都可用。
- 有候选时是可点选的单选 + 「其他」自定义输入；无候选时退化为纯文本输入。
- 点击 / 提交后即时回传，卡片折叠为「已选择：XXX」，Agent 在同一轮继续执行。
- 刷新页面不保留已失效卡片；答案折叠态在会话内保存。

## 关键代码位置

- 工具与通道：`src/core/ask.py` 的 `ask_user()` / `register()` / `set_asker()` / `has_asker()`
- 循环内调用：`src/core/agent.py` 的 `_ask_user()`
- 后端桥接：`src/core/webui.py` 的 `UIWebUI.ask_user()` / `_bridge_ask()`、`_Session.answer_ask()` / `deny_pending_ask()` / `acquire_ask_slot()`
- 前端：`web/src/components/Chat.tsx` 的提问卡片渲染
- 测试：`tests/test_ask.py`（返回协议 / 选项规范化 / 工具契约 / 等待桥）

## 注意事项

- 提问等待不阻塞其他会话；但同一会话的 run 仍保持串行。
- 被停止或断连时不会无限等待，Agent 会带着「未回答」继续。
- 提问卡片与危险确认是两套机制：前者问信息，后者要授权。
- 模型能从上下文推断或可用默认值时不应打断用户，这由系统提示约束。
