# 附件上传

## 用途

把图片与文件带进对话：图片走视觉通道，文件内容注入消息，助手回答里引用的图片可直接渲染。

## 概念

- **上传**：输入区左侧加号菜单，可多选图片 / 文件。
- **图片通道**：附件写入工作区 `.attachments/`，通过 `view_image` 的通道进入模型（`#img:<sha256>` 占位，事件流里不重复存正文）。
- **文件注入**：文件内容以文本形式注入消息；二进制文件不适合直接注入。
- **渲染**：助手回答中引用 `.attachments/` 路径的图片直接显示。

## 使用方式

1. 点输入区左侧「+」，选择图片或文件。
2. 发送消息，模型会自动看到附件内容。
3. 需要模型读文件内容时，也可以直接在对话里给出工作区路径，让模型用工具读取（更适合大文件与办公文档）。

## 支持与边界

- 图片格式按魔数嗅探，不只看扩展名。
- 文本附件有大小限制；超大或二进制文件应让模型用工具分块读取。
- `.attachments/` 是工作区内的隐藏目录，工作台文件列表不显示。

## 关键代码位置

- 上传接口：`src/core/webui.py` 的 `_handle_upload()`、`_attachment_file()`、`_resolve_attachments()`
- 图片通道：`src/core/images.py` 的 `attach_image()` / `take_images()`
- 消息拼装：`src/core/agent.py` 的 `_build_user_message()`
- 视觉工具：`builtin_tools/vision_tools.py` 的 `view_image`
- 前端：`web/src/components/Chat.tsx` 的附件菜单与消息渲染
- 测试：`tests/test_vision.py`

## 注意事项

- 图片与办公文档的处理路径不同：图片走视觉模型，`.docx` / `.xlsx` / `.pdf` 应让模型用对应工具读取，不要直接塞二进制。
- `.attachments/` 与 `.memory/` 一样是受保护目录，模型 / 脚本不能随意读写。
- 附件消息的会话标题会用文件名占位。
- 上传的文件保存在当前工作区下，换工作区不会带过去。
