# 已知问题与生产化缺口

## 用途

把「当前不是生产系统」这件事说清楚：哪些是设计边界、哪些是待补能力、哪些只是误报。接手时先读这一页，避免把预期当缺陷。

## 能力缺口（按优先级）

### 1. 权限规则引擎

判断粒度只有「整个工具是否 dangerous」这一层，读范围也只有一套对所有工具生效的全局策略。缺按工具 / 参数 / 路径逐条配置的规则（如「`read_file` 只允许某目录」「`run_shell` 禁止某类命令」），无法为不同场景配不同策略。

### 2. 跨运行追踪与成本归因

`run_id` 只标识单次运行，不串成 trace，回答不了「一次用户请求跨了几次运行、触发了哪些工具」。也缺单价表与金额换算，无法按模型 / 会话 / 工作区统计费用。

### 3. 语义检索

记忆召回依赖字符重合与关键词计数，同义改写（「部署」/「上线」）命中不了。缺向量索引与 embedding，条目变多后召回会持续退化。

### 4. MCP 双向能力

缺 resources / prompts / sampling 的调用入口；服务端主动发来的 `notifications/progress` 与 `roots/list` 无人处理（入站带 `id` 的请求落进 `_rx` 后没有消费者），进度与反向请求都会丢失。

### 5. 后端语音能力

只有浏览器 Web Speech API，依赖厂商云端、Firefox 不可用；缺离线 ASR（本地模型）与 TTS 输出，无法满足「数据不出本机」。

### 6. 线程级取消

纯 Python 阻塞调用无法被取消令牌打断（Python 不能安全杀线程），长耗时工具只能等它自己返回；MCP 侧也仍缺服务端请求的应答通道。

### 7. 权限模型与数据隔离

账号只有 `superadmin` / `user` 两档，作用是区分谁在登录；所有账号共用同一份会话、工作区、模型配置与记忆。没有按用户 / 按工作区的权限与隔离。

### 8. 局域网安全

局域网走明文 HTTP，密码在链路上可被同网段嗅探；只建议可信网络使用。`--no-login` 等于把本机文件与命令交给任何能访问端口的人。

## 沙箱边界（设计如此，不是 bug）

- 沙箱外写入 / 删除 / 移动**永远硬禁**，没有放开开关。
- `sandbox_read=open` 只降低读门槛，不改变写门槛。
- shell 与 Python 是完整语言，变量拼接、编码、别名等混淆写法无法 100% 拦截；工具通道、prelude、命令检测是纵深防御，不是绝对边界。
- `.memory` 与 `.attachments` 是保护区，工具与脚本不可见 / 不可读写。

## 界面与运维的已知小缺口

- 工具管理页只展示清单与标记，**没有搜索框，也没有 MCP 连接状态面板**；要排查连接看启动日志。
- 客户端断开（关页面 / 断网）时，后端偶尔会在日志里打印 `ConnectionResetError` 堆栈；属于已处理路径上的日志噪声，不影响任务。
- 附件上传的完整链路缺少自动化用例（图片通道有测试，上传 UI 需要手动验证）。
- 热重载只覆盖技能；工具模块与 `mcp_servers.json` 改动需重启后端。
- 会话的用量统计只有本轮与总量，没有跨会话 / 跨模型的成本汇总。

## 常见误报（不是缺陷）

| 现象 | 说明 |
|---|---|
| 顶栏某些操作无法用自动化点击验证 | 自动化限制，用户手动可操作 |
| `write_file` 在工作区内不弹确认 | 按设计：工作区内写入不属于危险操作；危险确认针对 `dangerous` 工具与 MCP |
| 系统配置页底部「关闭」按钮看起来无效 | 误报；关闭由外层壳处理 |
| 快速对话不显示推理等级 | 设计如此：快速对话显式关闭思考 |
| 豆包没有 Max 选项 | 豆包接口只认 low / high |
| 关闭技能后仍能在消息里显式注入 | 不会生效：停用技能在显式注入时也被忽略 |
| 局域网 http 下 PWA 不注册 | 浏览器要求安全上下文；localhost 或 https 才启用 |

## 生产化前的最小清单

1. 反向代理 + HTTPS，配置 `MINI_AGENT_ALLOWED_HOSTS`。
2. 补权限规则引擎，至少做到「按工具 + 按目录」。
3. 加跨运行 trace 与成本统计。
4. 为记忆加 embedding 召回。
5. 明确多用户隔离策略，或直接限定「单用户本机使用」。
