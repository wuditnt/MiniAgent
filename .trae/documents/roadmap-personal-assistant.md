# 迭代路线：迈向「强大的个人工作智能助手」

> 参考坐标：**DeepSeek Harness（dsh）** —— Agent = Model + Harness，「一切皆可扩展、每一次运行都有迹可循」。
> 本文把 dsh 的设计原则映射到本项目的现状，给出分阶段、可验证、可回滚的实施方案。

---

## 1. 目标与参照系

**终局目标**：一个本地优先、可扩展、记得住你、能主动干活的**个人工作智能助手** —— 而不只是一个「能调工具的对话控制台」。

dsh 给出的四条设计原则，正好是本项目要补齐的四条主轴：

| dsh 原则 | 含义 | 本项目的对应问题 |
| --- | --- | --- |
| **一切皆可扩展 / 无特权内核** | Cordis 内核只管「加载/卸载 + 依赖」；模型、工具、会话、沙箱、存储、循环、调度、UI 都是可替换的扩展点 | 「可扩展」目前只覆盖**工具模块**；模型适配器、会话存储、沙箱、循环都是硬编码在 `src/core` 里，换不了 |
| **每一次运行都有迹可循** | append-only 会话日志记录模型看到的一切；Trajectory 按来源查看；resume / fork / search / replay 共享同一事件流 | 只有分类**文件日志**（排查用）与**会话 JSON**（存 messages）；没有「模型可见」的事件流，无法回放/分叉/重建请求 |
| **多种运行模式** | Standard / PTC(Code) / Minimal / Creator，每种模式默认加载不同的能力集合 | 已有 chat / agent 双模式，但模式是**代码里写死**的分支，不是「可组合的能力集合」 |
| **能力可替换** | 模型适配器、工具注册表、会话日志、循环本身都是可替换的扩展点 | 无抽象层，替换任一能力都要改核心 |

同时保留本项目已确立的两条**硬底线**（任何路线都不得破坏）：
1. 沙箱外**一律禁止**写入 / 删除 / 移动，无任何开关可绕过；
2. `dangerous` 的 MCP 工具在**任何档位**都强制弹窗确认。

## 2. 现状盘点

### 2.1 已经很强的地基（继续保留）

- 核心循环 ~250 行（[agent.py](file:///d:/codeworks/mini-agent/src/core/agent.py)），`Tool` 统一对象、`@tool` 自动推导 schema，加工具不改核心。
- 三条扩展路径（用户工具文件 / 连接（MCP） / 内置工具）+ 技能（SKILL.md 清单 + 按需加载）。
- 沙箱双通道（`safe_path` 写 / `read_path` 读三档）+ 越界写检测 + Python prelude 写护栏 + zip-slip 防护。
- 三档确认（ask / auto / full）+ `request_approval`；MCP 危险工具硬弹窗。
- 记忆三层（用户画像 / 项目记忆 / 主题摘要）+ 自动提炼 + `.memory` 保护区。
- Web UI：双模式、流式、并行、取消、附件、会话持久化与搜索、工作台抽屉、系统配置、用量面板。
- 分类文件日志（app / llm / tool / error）、13 套免费测试 + 1 真实套件。

### 2.2 与「个人工作助手」的差距

| 差距 | 现状 | 影响 |
| --- | --- | --- |
| **无事件流 / 不可回放** | 会话只存 messages；日志非「模型可见」 | 无法调试「模型到底看到了什么」、无法回放/分叉、无法做成本归因的精确来源 |
| **内核未抽象** | 模型适配器/会话存储/沙箱/循环写死 | 换 provider、换存储、加模式都要动核心 |
| **记忆只支持关键词** | `render_memory_block` 按关键词命中 | 记忆一多召回退化，「助手记不住你」 |
| **权限粒度粗** | 三档 + `dangerous` 二值 | 无法「只允许读某目录」「某工具仅 ask」 |
| **无主动性** | 纯被动应答 | 不会「到点提醒」「监控目录变化」「自己盯任务」 |
| **无目标/计划/子 agent** | 单轮工具循环 | 长任务无法拆解、主上下文易膨胀 |
| **无成本归因** | 有 token 用量，无金额 | 不知道钱花在哪 |
| **集成面窄** | MCP 仅 tools/list + tools/call | 拿不到外部 resources/prompts，服务端反向请求无人应答 |
| **无多用户/远程** | 单用户本地 | 手机/远程日常不可用 |

## 3. 迭代原则

1. **每阶段独立可验证、可回滚**：每阶段结束跑通全量测试（含新增套件），并更新 README。
2. **新能力优先走「工具模块 / 连接」，尽量不改核心循环**——延续项目唯一目标。
3. **先地基后能力**：可追溯事件流（P0）与内核抽象（P1）先行，后续阶段都建立在其上。
4. **安全与可观测不后置**：治理（P3）放在「主动性」（P4）之前——先有护栏，再放开手脚。
5. **硬底线不动**：沙箱外禁写、MCP 危险工具弹窗，任何阶段不放开。

## 4. 分阶段实施方案

### P0 · 可追溯运行内核（Traceable Run）

**目标**：把「模型看到的一切」写进一条 append-only 事件流，支撑回放 / 分叉 / 检索 / 重建。
**为什么先做**：它是后续记忆沉淀（P2）、成本归因（P3）、子 agent 调度（P4）的共同数据源；也是 dsh 最核心的差异点。

**关键改动**
- 新增 [`core/events.py`](file:///d:/codeworks/mini-agent/src/core) → `core/events.py`：会话事件流（JSONL，仅追加）。事件类型：
  `system_prompt`、`user_message`、`context_inject`（记忆块 / 技能清单 / 摘要 / 裁剪）、`llm_request`、`llm_response`（usage + 摘要）、`tool_call`、`tool_result`、`approval`、`cancel`、`error`。每条事件带 `source` / `phase` / 时间戳。
- 会话存储升级：`web_data/sessions/<id>.json`（messages）→ **事件流 + 物化视图双写**；`resume` 从事件流重建 messages（保证「模型可见即已记录」）。
- [agent.py](file:///d:/codeworks/mini-agent/src/core/agent.py) 在关键点 `emit`：system prompt 重建、注入记忆、每轮 LLM 请求/响应、每个工具调用与结果、裁剪与摘要。
- 前端新增 **Trajectory 视图**：`web/src/components/Trajectory.tsx`，按 source 着色、可展开、可回放单轮；会话列表增加「回放」入口。
- 新增不变式测试：一次真实/mock 运行后，**每条 LLM 请求都能由事件流重建**（`tests/test_events.py`）。

**验收**：一次运行可从事件流完整重建每条模型请求；Trajectory 视图可回放；13 套件回归全绿。

**风险/取舍**：事件流会让会话文件变大 → 采用 JSONL + 定期压缩（保留摘要层），消息体截断存储、完整正文只在进行中保留。

---

### P1 · 可扩展内核（Kernel + Extensions）

**目标**：把「一切皆可扩展、无特权内核」落地 —— 模型适配器 / 工具注册表 / 会话存储 / 沙箱 / 审批 / 记忆 / 调度 / UI 都成为**可配置替换的能力提供方**。

**关键改动**
- 新增 `core/kernel.py` + `core/services.py`：极简内核，只做 **装载 / 卸载 / 依赖声明 + 服务注册 + 事件总线**。
- 把现有隐式能力抽象为接口：
  `ModelProvider`（现 `model_config` + 客户端构建）、`ToolRegistry`（已有）、`SessionStore`（P0 事件流）、`SandboxPolicy`（现 `sandbox.py`）、`ApprovalPolicy`（现 `approval.py`）、`MemoryStore`（现 `memory.py`）。后续 P4 的 `Scheduler` 也走同一套。
- **预设（profile）** 在配置层组合能力集合：`standard / chat / code(PTC) / minimal`，对应 dsh 的多种运行模式；[loader.py](file:///d:/codeworks/mini-agent/src/core/loader.py) 从「加载工具模块」扩展为「加载能力扩展」，声明 `PROVIDES` / `REQUIRES`；卸载时**撤销注册**（副作用回滚，无特权内核）。
- 保持向后兼容：现有 `builtin_tools/*.py`（`@tool`）默认作为「工具扩展」，无需改写。

**验收**：不改核心代码即可替换**会话存储**与**模型适配器**；至少两个预设可切换且工具集随之变化；扩展卸载后注册项干净回滚。

---

### P2 · 记忆 2.0（语义检索 + 结构化沉淀）

**目标**：从「关键词命中」升级为「记得住你」——语义检索 + 结构化条目 + 时间衰减。

**关键改动**
- 新增 `core/memory_index.py`：embedding 索引（本地 Ollama `bge-m3` 或配置的 embedding provider），**混合召回**（关键词 BM25/子串 + 向量），带**时间衰减**与**标签过滤**。
- 记忆条目结构化：`- 时间 · 来源 · 标签 · 置信度 — 正文`，写入与解析兼容旧格式。
- 自动沉淀接入 P0 事件流：从「决策 / 偏好 / 踩坑」事件提炼，去重阈值沿用现有 ≥0.88。
- 注入预算重排：画像/项目记忆优先，主题摘要按相关度取 top-k（现注入逻辑在 [memory.py](file:///d:/codeworks/mini-agent/src/core/memory.py#L294-L329)）。
- 设置 → 记忆页签增强：搜索框、去重、冲突合并、按标签筛选。

**验收**：构造 100+ 条记忆，语义查询的召回明显优于关键词基线；注入不超预算；`.memory` 保护区规则不回退。

---

### P3 · 治理：细粒度权限 + 成本/审计（Policy & Observability）

**目标**：给出「赋予更大权限」的安全底座，并让钱与时间可归因。

**关键改动**
- `approval.py` 演进为 `core/policy.py`：**规则引擎**，按 `工具 / 参数 / 路径 / 域名` 做 `allow / deny / ask`，与三档模式**叠加**（规则优先，档位兜底）。规则文件 `web_data/policy.json`（可选工作区级覆盖）。
  - 例：`read_file` 仅某目录 allow；`run_shell` 一律 ask；某 MCP server 白名单。
- 成本归因：内置模型单价表 → 每轮 / 每会话 / 每工作区**金额**；基于 P0 事件流的 token 与耗时。
- 前端用量面板增强：成本列、按模型/来源分组；调用链 span（每轮耗时分解：模型 / 工具 / 确认）。
- **审计**：危险操作、越权尝试、规则命中写入独立审计流（接 P0）。

**验收**：可配置「`read_file` 仅某目录 allow、`run_shell` 一律 ask」并生效；面板显示每会话成本；越权尝试出现在审计流。

**硬约束**：本阶段规则引擎**不得**提供「放开沙箱外写入」的开关。

---

### P4 · 主动性：目标 / 计划 / 调度 / 子 agent

**目标**：从「被动应答」跨到「主动干活」——这是「工作助手」的分水岭。

**关键改动**
- **目标与计划**：新工具模块 `builtin_tools/plan_tools.py`（`plan_task`、`update_todo`、`list_todos`），前端「目标 / 待办」面板。
- `core/scheduler.py`：cron / 一次性 / **事件触发**（文件变更、时间、外部 webhook）→ 到点**主动发起会话**并经通知栏告知；持久化 `web_data/schedules.json`。
- `core/subagent.py`：长任务派生**子 agent**（独立上下文 + 受限工具集 + 独立沙箱边界），主循环只取「结论摘要」，避免主上下文膨胀；可并发。
- **主动性护栏**：跨出沙箱 / 联系外部 / 产生费用前，一律走 P3 的策略与审批。

**验收**：能创建「每天 9:00 汇总某目录变更」的定时任务并主动执行；一个大任务能拆给子 agent 且主上下文不膨胀；越界动作被拦。

---

### P5 · 集成与多模态（Connectors & Multimodal）

**目标**：连接你的世界（外部数据源 / 浏览器 / 桌面 / 语音）。

**关键改动**
- MCP 高级能力补全（[mcp.py](file:///d:/codeworks/mini-agent/src/core/mcp.py) 现仅 `tools/list` + `tools/call`）：
  - `resources`（外部数据源作为上下文注入，走 P0 的 `context_inject`）；
  - `prompts`（提示模板）；
  - `sampling`（服务端反向调用模型）；
  - 进度通知 + **server→client 请求处理**（补上取消一节的已知缺口）。
- 语音：ASR 输入 + TTS 播报（`web` 侧录音、`images.py` 同级的音频通道）。
- 桌面 / 浏览器自动化：接入 computer-use MCP、浏览器扩展，完成「检索 → 归档」这类真实动作。

**验收**：能从外部 MCP resource 拉取上下文；语音可输入；能驱动浏览器完成一次检索归档。

---

### P6 · 产品化：远程 / 多用户 / 打包（Deployment）

**目标**：日常可用、可远程、可多用户。

**关键改动**
- 远程访问 + **多用户 / 权限体系**（此前已明确「未来会考虑」）：每用户工作区、记忆、会话隔离；远程侧栏按角色隐藏管理入口（沿用既有约定）。
- 打包：Docker / 桌面客户端；密钥托管；会话与记忆的备份 / 迁移。
- `scripts/` 增加一键部署脚本；README 增部署章节。

**验收**：部署后远程/手机可用且数据隔离；一条命令启动。

## 5. 顺序与依赖

```
P0 事件流 ──► P1 内核 ──► P2 记忆2.0
                  │            │
                  ├──► P3 治理（策略/成本/审计）──► P4 主动性（目标/调度/子agent）
                  │                                            │
                  └──────────────────► P5 集成与多模态 ─────────┘
                                                               │
                                                          P6 产品化
```

- P0 是**所有阶段的地基**（记忆沉淀、成本、回放、子 agent 都依赖它）。
- P3 必须在 P4 之前：**先有护栏，再放开主动性**。
- P1 与 P2/P3 可部分并行（内核抽象不阻塞记忆索引）。

## 6. 里程碑

| 里程碑 | 交付 | 判定标准 |
| --- | --- | --- |
| M1（P0） | 事件流 + Trajectory 视图 | 可从事件流重建请求；可回放 |
| M2（P1） | 可扩展内核 + 预设 | 可换存储/模型适配器；预设可切 |
| M3（P2） | 语义记忆 | 语义召回明显优于关键词 |
| M4（P3） | 策略引擎 + 成本面板 | 细粒度规则生效；成本可查 |
| M5（P4） | 主动性 | 定时/触发任务主动执行；子 agent 可用 |
| M6（P5） | 集成与多模态 | 外部资源 / 语音 / 浏览器打通 |
| M7（P6） | 产品化 | 远程多用户可用、一键部署 |

## 7. 风险与取舍

- **事件流体积**：JSONL 会持续增长 → 正文截断存储 + 摘要层 + 定期压缩；不牺牲「可重建请求」这一不变式。
- **内核化的复杂度**：勿过度设计——内核保持「只管加载/卸载/依赖」，具体能力一律留在工具模块里。
- **记忆索引成本**：embedding 优先本地模型，避免把隐私数据发给第三方；云端 embedding 作为可选。
- **主动性的打扰**：调度与子 agent 必须可静音 / 可审计，默认不主动联系外部。
- **多用户是最大改动的单体**：建议放在最后，且以「每用户工作区隔离」为最小可用形态先行。

## 8. 每阶段完成定义（DoD）

1. 全量测试（含新增套件）通过，且不回归 13 套件；
2. 新增能力有独立可回滚的配置开关；
3. `README.md` 对应章节更新；
4. 两条硬底线（沙箱外禁写、MCP 危险工具弹窗）经测试验证未被破坏。
